# Clip2MD 设置页简洁化改版说明书

日期：2026-08-17  
状态：设计已确认，等待书面审阅  
适用页面：`src/options/options.html`、`src/options/options.css`、`src/options/options.ts`

## 1. 背景

当前设置页功能完整，但所有配置按长表单顺序平铺，常用项、条件项和高级项拥有接近的视觉权重。用户需要阅读较多说明文字，才能判断内容最终保存到哪里，以及哪些下载设置当前会生效。

截图和代码检查显示以下主要问题：

1. “自定义文件夹”与“浏览器下载目录”属于同一个保存决策，却被快捷键和分隔线隔开，生效条件只能依赖标题中的长括号说明。
2. 主要按钮分散在页面各处，包含选择文件夹、调整快捷键、保存设置和测试连接，缺少明确的主次关系。
3. Obsidian 配置是低频高级功能，却始终完整展开，显著增加页面长度。
4. 标题、字段、提示文字之间主要依靠纵向间距区分，分组边界较弱。
5. CSS 只统一处理了 `input[type="text"]`；API Key 使用 `type="password"`，因此截图中该输入框保持浏览器默认样式，与其他字段不一致。
6. 保存反馈、文件夹反馈和连接反馈的样式与位置不完全统一，用户需要在不同区域寻找结果。

## 2. 设计目标

改版需要同时满足以下目标：

- 用户进入页面后，首先明确当前实际保存位置。
- 常用设置直接可见，低频配置按需展开。
- 减少长说明、长标题和散落按钮造成的视觉噪声。
- 保留现有设置字段、存储结构和核心行为，避免无关功能改动。
- 建立一致的输入框、按钮、状态反馈和键盘焦点样式。
- 在常见桌面宽度和窄窗口下保持清晰、可操作、不横向滚动。

## 3. 非目标

本轮不包含：

- 修改 Markdown 保存、下载、快捷键或 Obsidian API 的底层业务逻辑。
- 新增云同步、账户体系、主题切换或其他设置项。
- 重构 `core/settings.ts` 的持久化结构。
- 改版扩展弹窗、侧边栏或内容提取页面。
- 引入新的前端框架或组件库。

## 4. 方案选择

采用已确认的 **A 方案：单列分组卡片**。

该方案在现有页面规模下提供足够清晰的层级，同时不引入侧栏导航或全折叠手风琴的额外复杂度。常用项保持可见，只有条件项和高级项折叠。

未采用的方案：

- 侧栏导航：扩展性较强，但当前设置数量不足，结构成本高于收益。
- 全折叠手风琴：首屏较短，但增加点击次数并降低设置状态的可发现性。

## 5. 信息架构

页面按以下顺序组织：

### 5.1 页面标题

- 标题：`Clip2MD 设置`
- 副标题：`配置 Markdown 文件的保存方式`
- 不增加额外品牌横幅、插图或营销文案。

### 5.2 保存位置卡片

这是页面的第一张卡片，用于回答“内容现在会保存到哪里”。

当已选择自定义文件夹时：

- 显示文件夹图标、文件夹名称和“已连接”状态。
- 显示“更改”次要操作和“清除”文字操作。
- 说明内容将直接写入该文件夹，并绕过浏览器下载目录。
- “备用下载设置”默认收起，标题旁明确标注“仅未选择自定义文件夹时生效”。

当未选择自定义文件夹时：

- 显示“未选择自定义文件夹”状态和“选择文件夹”主要操作。
- 自动展开备用下载设置。
- 备用下载设置包含浏览器下载子目录和“每次保存时询问位置”复选框。

清除文件夹后，不弹出阻塞式确认框；在卡片内显示成功反馈，并立即切换到浏览器下载配置状态。

### 5.3 快速保存卡片

- 左侧显示功能名称和一句短说明。
- 右侧使用键帽样式显示当前快捷键。
- “修改”作为文字操作，打开 Chrome 官方快捷键页面。
- 读取失败或未绑定时，在同一区域显示明确状态，不改变卡片结构。

### 5.4 Obsidian 高级设置卡片

- 默认收起，标题行显示 Obsidian、用途说明和“高级设置”标签。
- 展开后依次显示 Local REST API 地址、API Key、笔记目录和测试连接操作。
- API Key 使用完整输入框样式，并提供“显示/隐藏”切换；默认隐藏。
- “测试连接”使用次要按钮，结果在按钮旁就近显示。
- 展开状态只服务当前页面会话，不新增持久化字段。

### 5.5 保存操作区

- 页面底部设置统一保存操作区。
- 用户未修改字段时，“保存更改”按钮禁用。
- 用户修改任一可持久化字段后，按钮启用。
- 保存中显示加载状态并防止重复提交。
- 保存成功、失败均在按钮左侧显示简短状态文字。
- 选择文件夹、清除文件夹和测试 Obsidian 连接仍按现有行为即时执行；底部按钮只负责原有表单字段。

## 6. 视觉规范

### 6.1 布局

- 页面背景：`#f6f8fb`
- 主内容最大宽度：`680px`
- 建议内容宽度：`620px–680px`
- 页面左右安全间距：窄窗口 `16px`，常规窗口 `24px`
- 卡片间距：`14px`
- 卡片内边距：`20px`

### 6.2 色彩

- 主色：`#2563eb`
- 主要文字：`#172033`
- 次要文字：`#667085`
- 边框：`#e1e7ef`
- 页面背景：`#f6f8fb`
- 成功：`#18794e`
- 错误：`#b42318`

颜色使用原则：主色只用于主要操作、焦点和可点击文字；成功与错误色只用于状态反馈。页面不使用渐变、大面积品牌色或强阴影。

### 6.3 字体与控件

- 沿用系统字体栈和现有中文字体回退。
- 页面标题：`24px`，字重 `700–760`。
- 卡片标题：`15px`，字重约 `700`。
- 正文与控件：`14px`。
- 辅助文字：`12px`，行高不低于 `1.5`。
- 输入框和按钮高度：`36px–40px`。
- 输入框圆角：`8px`；卡片圆角：`14px`。
- 阴影只用于轻微分离卡片，不能替代边框。

### 6.4 操作层级

- 主要按钮：蓝底白字，同一视区原则上只出现一个。
- 次要按钮：白底、灰色边框。
- 文字操作：无背景，用于“修改”“清除”“显示”等低权重动作。
- 危险或清除动作只在悬停、聚焦时使用错误色，避免常态抢夺注意力。

## 7. 交互与状态

### 7.1 展开与收起

- 备用下载设置：由自定义文件夹状态决定默认展开状态，用户仍可手动展开查看。
- Obsidian：页面初次打开时默认收起，用户可手动切换。
- 折叠标题行整体可点击，并提供明确的展开图标与 `aria-expanded`。

### 7.2 表单状态

- 所有文本和密码输入框共享正常、悬停、聚焦、禁用和错误样式。
- 聚焦状态不能只依赖颜色，应有可见焦点轮廓。
- 字段错误在字段下方显示，并与对应输入框建立辅助描述关系。
- 子目录仍使用现有 `sanitizeSubfolder` 逻辑；改版不改变清洗规则。

### 7.3 反馈状态

状态反馈统一分为：

- 中性：加载中、已取消、未绑定。
- 成功：文件夹已连接、设置已保存、Obsidian 连接成功。
- 错误：权限失败、读取失败、保存失败、连接失败。

状态文字就近出现，并使用 `role="status"` 或合适的 `aria-live` 区域。错误信息应保留可操作线索，例如“请检查地址或 API Key”，避免只显示“失败”。

### 7.4 键盘与无障碍

- 所有操作可通过 Tab 到达，并有清晰的 `:focus-visible` 样式。
- 卡片标题使用正确的标题层级；折叠控件使用原生按钮或 `details/summary`。
- 输入框保持可见标签，不用 placeholder 替代 label。
- 点击目标不小于约 `36px` 高。
- 状态颜色必须同时配合文字或图标表达含义。

## 8. 数据与代码边界

改版沿用现有数据流：

1. 页面加载时通过 `loadSettings()` 恢复表单字段。
2. 自定义文件夹句柄继续通过 `loadDirectoryHandle()`、`saveDirectoryHandle()` 和 `clearDirectoryHandle()` 管理。
3. 快捷键继续通过 `chrome.commands.getAll()` 读取，并跳转到 `chrome://extensions/shortcuts` 修改。
4. 底部保存操作继续调用 `saveSettings()`。
5. Obsidian 测试继续先保存当前字段，再发送 `TEST_OBSIDIAN` 消息。

不新增设置字段，不迁移现有用户数据，不修改消息协议。新增的展开状态、脏状态和 API Key 显示状态均为页面内临时 UI 状态。

## 9. 预计修改范围

实施阶段只应触及与设置页直接相关的文件：

- `src/options/options.html`：重新组织语义结构和分组。
- `src/options/options.css`：建立卡片、控件、状态、响应式和焦点样式。
- `src/options/options.ts`：管理折叠、脏状态、API Key 显示切换与统一反馈。
- 设置页相关测试文件：补充关键状态和现有行为回归测试；若当前没有专用文件，可新增一个最小测试文件。

不应顺带修改 popup、adapter、background 或其他现有未提交改动。

## 10. 实施顺序

1. 建立设置页结构与 CSS 变量，保留全部现有元素 ID，确保 TypeScript 绑定不失效。
2. 统一文本输入框和密码输入框样式，完成卡片与响应式布局。
3. 加入备用下载和 Obsidian 折叠行为。
4. 加入表单脏状态、按钮禁用状态、API Key 显示切换和统一反馈。
5. 补充自动化测试，并进行真实扩展页浏览器验证。

每一步只处理当前目标，不重构无关代码。

## 11. 验收标准

### 11.1 视觉验收

- 页面在 `320px`、`560px` 和 `768px` 可视宽度下无横向滚动、重叠或文字截断。
- API Key 与其他输入框的尺寸、边框、圆角和焦点样式一致。
- 首屏能看见当前保存位置、快捷键和 Obsidian 折叠入口。
- 页面中不存在超过一个同等权重的主要按钮。
- 提示文字不依赖标题中的长括号表达关键生效条件。

### 11.2 功能验收

- 选择、读取、清除自定义文件夹的现有行为保持正常。
- 未选择自定义文件夹时，浏览器下载设置可见并可保存。
- 已选择自定义文件夹时，备用下载设置明确标记为当前不生效。
- 快捷键能正确显示，修改按钮能打开 Chrome 快捷键页面。
- 所有原有设置均可加载、修改并保存，刷新后保持一致。
- Obsidian API Key 默认隐藏，可切换显示与隐藏。
- 测试连接的成功、失败和加载状态均正确显示。
- 表单无改动时保存按钮禁用，有改动时启用，保存后恢复禁用。

### 11.3 工程验收

- `npm run typecheck` 通过。
- `npm test` 通过。
- `npm run build` 通过。
- 在 Chrome 中加载构建后的 `dist/`，完成设置页关键路径人工检查。
- Git diff 仅包含设置页、对应测试和经批准的文档变更。

## 12. 风险与控制

- **风险：** 重新分组时更改元素 ID，导致现有 TypeScript 查询失败。  
  **控制：** 第一阶段保留所有现有 ID；结构和样式稳定后再评估是否需要重命名。

- **风险：** 折叠后隐藏当前生效状态。  
  **控制：** 折叠标题始终显示状态摘要，例如当前文件夹名称或 Obsidian 是否已配置。

- **风险：** 脏状态漏掉程序性字段更新。  
  **控制：** 明确区分加载初始化与用户输入，测试每个可持久化字段的按钮状态变化。

- **风险：** 当前工作区已有其他未提交改动。  
  **控制：** 实施时只编辑设置页和专用测试文件，提交前使用精确路径检查 diff，不覆盖或整理无关改动。

## 13. 完成定义

当视觉、功能和工程验收全部满足，且没有改变现有设置数据或底层保存逻辑时，本次设置页简洁化改版才视为完成。
