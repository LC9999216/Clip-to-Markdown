## 一、交付目标

在不修改现有 `ContentDocument` 和 Markdown 保存协议、不新增静态浏览器权限的前提下，将「一图速览」升级为 V2：

- 用两句话摘要、核心观点和扁平内容结构呈现 X 内容；
- 为 X Article 建立确定性的原文块编号与短引用锚点；
- 用户点击内容结构后，仅在文章、块编号和短引用能够唯一匹配时滚动并高亮原文；
- 普通推文没有可靠锚点时保持静态结构，不伪装成可点击导航；
- 保留重新生成、会话缓存和原有 Markdown 保存链路。

## 二、主要交付内容

### 2.1 原文来源块

- 从 X Article 真实 DOM 中提取标题、段落、列表、引用、代码和表格等来源块。
- 使用稳定的 `B001`、`B002` 等编号；长块按边界切分但不修改正文协议。
- 分析与导航复用同一套来源块生成逻辑，避免两套规则产生偏差。

### 2.2 V2 分析与校验

- V2 输出包含恰好两条摘要、2 至 5 个核心观点和最多 10 条内容结构。
- X Article 的结构条目必须同时包含 `sourceBlockId` 和 `sourceQuote`；普通推文不得包含锚点。
- 短引用必须真实存在于发送给 AI 的来源块中，并且能够唯一匹配。
- 非法响应最多修复一次；超长文本和超量结构按边界安全截断。
- 官方 DeepSeek V4 模型的结构化分析请求使用 JSON 输出模式；其他 OpenAI-Compatible 服务不携带 DeepSeek 专用参数。

### 2.3 原文导航

- 导航前校验当前页面与生成摘要时的 X status ID 一致。
- 先按来源块编号和短引用匹配，必要时回退到全文唯一短引用匹配。
- 0 个或多个候选均拒绝跳转，避免错误定位。
- 唯一候选滚动到视口中央并短暂高亮；支持 `prefers-reduced-motion`。

### 2.4 Side Panel 与缓存

- Side Panel 按“文章信息 → 两句话看懂 → 核心观点 → 内容结构 → 操作”展示。
- 有锚点的结构条目使用按钮；无锚点条目保持静态文本。
- V2 结果和短原文引用仅写入 `chrome.storage.session` 会话缓存。
- 缓存键覆盖 schema 版本、来源 URL、实际 AI 正文、模型和 Endpoint，不包含 API Key。

## 五、隐私与安全边界

- 只有用户主动触发一图速览或重新生成时，才把当前 X 正文发送给用户配置的 AI 服务。
- API Key 仅保存在 `chrome.storage.local`，由扩展 Background 使用。
- 原文块编号和最多 140 字的短引用仅服务于当前会话的确定性导航。
- V2 结果不写入网页，不随 Markdown 保存链路写入导出正文。
- AI 文本继续使用原生 DOM 与 `textContent` 渲染，不使用 `innerHTML`。
- 没有新增静态 `host_permissions`、远程脚本、后端或账号系统。

## 六、已知边界

- 原文定位仅支持 X Article；普通推文只展示分析结构。
- X 页面 DOM 变化、正文尚未完整加载或短引用出现歧义时，导航会保守失败并提示用户重新生成，不进行相似度猜测。
- 本报告没有补写未记录的人工测试样本数量；如未来需要量化发布指标，应单独保存测试文章和逐章节矩阵。
